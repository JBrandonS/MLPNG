## Running

**Code has been designed to run on the SuperPOD and M2, local runs may need some modification.** 

Please see libs to see the required packages and versions.

### Data Directories
You will need to create a few files and directories before running the code. Currently these are 
- `data/` directory
- `data/models/` this will hold the models and checkpoints
- `data/plots/` holds some plots useful for debugging
- `data/tensorboard/` holds the tensorboard logs, if enabled

Some tests require data from Thomas's code these are in the following folders, these test can be disable / modified or you can copy my setup:
- `data/linear-thomas/` contains the outputs from Thomas's makemaps code, such as `fnls.npy` and `squaremaps_*.npy`
- `data/static/` holds static files that do not change such as the binning files use in `DenistyFields.py`, `HighLExtrapTemplate`, the `LinearTransfer`, and `PLinear` files.

> **NOTE:** SMU IT recommends using the `$SCRATCH` directory for this, this is a HPFS which makes it better for large datasets with almost 2x the thoughtput of the `$WORK` and `$HOME`. You can do this by making a data directory in your scratch directory and then linking it to the data directory in the repo.
> 
> ```bash
> mkdir $SCRATCH/data
> ln -s $SCRATCH/data data
> ```
>

### Data Generation

Once the directories are set you should be good run `dataGenerator.ipynb` to test. 

If you want to run in SLURM you can use `sbatch dataGenerator.sbatch`, this will run the `dataGenerator.py` script which is the same as the notebook but without the plots, it is manually generated by exporting the Jupyter Notebook. You might need to change some settings in the sbatch file which is configured to run on the SuperPOD.

This process is currently quite slow, taking around 30 seconds per map, so it will take a while to generate a large dataset. I am working on a way to speed this up. For now, consider only using the `dataGenerator.ipynb` notebook to generate a small dataset for testing. Run the sbatch longer datasets, for datasets over a million we will probably need to rework the save code to allow multiple nodes to run in parallel.

### Training

Once you have your data, you can use the `modelTrainer.ipynb` to train the model. This will save the model and checkpoints to the `data/models/` directory. I may eventually make a sbatch runner for this as well, but for now it is just the notebook.
